HCI Analysis: Redesigning SIA for Better Passenger Experience

This prototype improves passenger usability through accessibility, consistency, navigation, user feedback, and efficiency — the five core HCI evaluation criteria.

Project Scope

What This Prototype Covers

This is not a complete clone of SIA.com. It is an HCI redesign prototype focused on passenger-facing interactions.

Scope of Redesign

We focused on passenger-facing tasks only: booking, flight search, service discovery, support access, and accessibility features.

Mock Data Only

All flight data — routes, prices, schedules — is hard-coded. There is no real backend, no real payment, and no real booking processing.

Academic Prototype

This project exists to demonstrate HCI principles in a real-world airline context. Usability and interaction design are the primary goals.

Technology Used

HTML, Tailwind CSS (CDN), Vanilla JavaScript. No frameworks, no backend, no npm. Designed to run directly in any browser.

Why SIA?

Airline websites involve high-stakes user decisions: money, schedules, travel. They are an ideal HCI case study with clear usability problems to solve.

Target Users

Pakistani domestic travelers, international diaspora, and users with accessibility needs — ranging from tech-savvy to first-time digital bookers.

Core Evaluation Criteria

Five HCI Principles Applied

Each principle is mapped to a specific problem, our improvement, and where it appears in the prototype.

PRINCIPLE 01
Accessibility
Typical Problem

Airline websites are difficult for users with visual, motor, or cognitive limitations. Small text, poor contrast, unclear forms, and hidden support options make tasks frustrating or impossible for many passengers.

Our Improvement

We added a skip-to-content link, a fully interactive Accessibility Panel (high contrast, large text, reduced motion, link underline), visible focus states on all interactive elements, clearly labelled form fields, and a prominent Special Assistance section in the Contact page.

Appears in: All page headers Booking Widget Contact Page Accessibility Panel All Forms
PRINCIPLE 02
Consistency
Typical Problem

Inconsistent buttons, layouts, card styles, navigation patterns, and color usage increase cognitive load. Users must re-learn the interface on every page, slowing task completion and increasing error rates.

Our Improvement

We built a single global.css design system with tokens for color, spacing, typography, shadows, and radii. Every button, card, form field, navbar, and footer is reused across all six pages without modification, giving passengers a predictable experience.

Appears in: Navbar (all pages) Footer (all pages) Booking Form Service Cards Flight Cards
PRINCIPLE 03
Navigation
Typical Problem

Airline websites overwhelm users with too many scattered links, unclear menu hierarchy, and no active state to indicate current position. Users struggle to find core tasks like check-in, flight status, or booking support.

Our Improvement

We implemented a sticky navbar with dropdown menus, a mobile drawer, a search overlay (Ctrl+K), active page link highlighting, a Quick Services strip on the homepage, and clear CTA buttons in every section that guide users to the next logical step.

Appears in: Sticky Navbar Mobile Nav Drawer Hero Carousel CTAs Quick Services Strip Footer Links
PRINCIPLE 04
User Feedback
Typical Problem

Users are left guessing when they search, select, or submit. No loading states, no confirmation messages, no error correction hints. When mistakes happen — same city, empty fields — users receive no guidance on how to recover.

Our Improvement

Every critical action produces visible feedback: a loading spinner when searching flights, toast notifications for success/error/warning states, inline form validation, aria-live regions for screen readers, and an empty-state message when no flights match filters. Booking steps show clear progress.

Appears in: Booking Widget Flights Results Page Contact Form Booking Steps Toast Notifications
PRINCIPLE 05
Efficiency
Typical Problem

Passengers want to complete core tasks — book a flight, check in, find baggage info — in the fewest possible steps. Original airline sites bury key actions behind multiple menus, force unnecessary logins, and provide no shortcut to frequent tasks.

Our Improvement

The booking widget is above the fold on the homepage with city autocomplete and a route-swap button. Quick services reduce navigation steps. Flight filters (sort by price/time/duration, filter by class) reduce scanning effort. Passenger counter replaces manual text entry. The whole booking flow is guided and linear.

Appears in: Homepage Booking Widget Flights Page Filters Quick Services Row City Autocomplete Passenger Counter
Before vs After

What We Improved

Concrete comparisons between common airline website problems and our HCI-driven solutions.

Original Issue

Scattered service links buried in sub-menus with no grouped quick-access strip.

Our Redesign

A horizontally scrollable Quick Services strip directly below booking — Check-In, Flight Status, Manage Booking, Cargo all visible in one row.

HCI Benefit: Faster task discovery
Original Issue

Form errors only shown on submit, with no inline guidance or clear error messages.

Our Redesign

Inline validation on blur, same-city prevention, required field highlights, and toast notifications with clear error messages on every form.

HCI Benefit: Better error recovery
Original Issue

No accessibility tools visible — users with special needs must call a helpline with no digital alternative.

Our Redesign

Persistent Accessibility Panel with font size control, high contrast, reduced motion. Dedicated Special Assistance section on Contact page with a direct request form.

HCI Benefit: More inclusive experience
Original Issue

Flight search returns a cluttered list with no sorting or filtering — users must manually compare every option.

Our Redesign

Flight results page includes sort (price, depart, duration) and class filters. Loading state gives clear feedback. Empty state explains when no results are found.

HCI Benefit: Reduced decision fatigue
Original Issue

Mobile navigation is collapsed into a hamburger with no visual feedback and poor touch targets.

Our Redesign

Mobile drawer with animated hamburger, large touch targets (44px minimum), full list of page links, and a prominent Book a Flight CTA at the bottom.

HCI Benefit: Better mobile usability
Original Issue

No active page indicator in navigation — users cannot tell where they are in the site structure.

Our Redesign

Active nav link is highlighted with a green underline and background. Current page is detectable by JavaScript matching the URL — consistent across all six pages.

HCI Benefit: Clear navigation context
For the Presentation

Talking Points

Key points to raise when the teacher asks about HCI application in the project.

1

Why SIA? We chose SIA because airline websites involve high-stakes real-world decisions — booking travel, spending money, managing time. This makes them ideal for HCI analysis where usability directly impacts user outcomes.

2

Scope decision: We chose not to clone the entire SIA website. Instead we focused on the passenger task flow — search, discover, book, get help — because HCI is about the quality of interaction, not the quantity of pages.

3

Booking Widget (Efficiency): The booking widget on the homepage demonstrates efficiency. It uses city autocomplete to reduce typing errors, a swap button to reverse route, a passenger counter to avoid free-text entry, and date validation to prevent impossible departure dates.

4

Accessibility Panel (Inclusive Design): The persistent Accessibility Panel demonstrates inclusive design — a concept central to HCI. It is visible on every page and lets users with different needs adjust font size, enable high contrast, or reduce motion without needing a special version of the site.

5

Flights Results Page (Feedback + Efficiency): The flights page shows a loading state while "fetching" results, renders flight cards with all critical information visible at a glance, provides sort and filter controls, and shows a meaningful empty state when no flights match the route — all examples of user feedback and efficiency.

6

Contact Page (Accessibility + Navigation): The contact page groups support options by topic (Call, Email, Baggage, Refund, Special Assistance) reducing navigation effort. The special assistance section is prominently placed — not buried — because users with accessibility needs should not have to work harder to find help.

7

Mock Data rationale: HCI evaluates interaction quality and usability, not backend systems. Using mock data allows us to demonstrate the complete user journey — from searching to confirming a booking — without the complexity of a real server, which is not the focus of an HCI course project.
